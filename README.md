# Сауша-бот (Анонимный бот)

Комплекс из двух Telegram-ботов для анонимного общения в Telegram-канале:
1. **Бот 1 (aiogram 3)**: анонимные комментарии к постам канала через группу обсуждения. Пользователям присваиваются псевдонимы (эмодзи + код) для различения участников. Защита от спам-ботов, проверка подписки на чат.
2. **Бот 2 (python-telegram-bot 20)**: анонимные сообщения (предложка) в канал, модерация контента (SightEngine для фото/видео/стикеров), еженедельный топ активных пользователей, админ-панель с логами и блокировками.

## Секретная админка

В обоих ботах панель открывается командой:

```
/admin подкушано67
```

- команду может ввести **любой пользователь**, но панель выдаётся только при верном пароле;
- пароль задаётся переменной окружения `ADMIN_SECRET` (по умолчанию `подкушано67`);
- после успешного входа сообщение с паролем удаляется из чата;
- доступ действует до перезапуска бота: после рестарта нужно ввести команду заново;
- уведомления о новых и заблокированных анонимках приходят на `ADMIN_ID` и **всем, кто ввёл пароль**, пока бот работает;
- `ADMIN_ID` по-прежнему нужен — это владелец: он получает уведомления всегда, даже если ещё не вводил команду.

Смените пароль в Render → **Environment** → `ADMIN_SECRET`, не храните его в коде публичного репозитория. Пароль — единственная защита: кто его знает, получает полный доступ к логам, рассылке и блокировкам.


## Ручная публикация заблокированных анонимок

Если анонимка не прошла проверку Sightengine, админ всё равно получает её в личку с причиной блокировки. Под уведомлением есть кнопка **«✅ Опубликовать как анонимку»** — по нажатию сообщение публикуется в канал как обычная анонимка (с шапкой, подписью и учётом в топе).

- кнопка видна и работает только у того, кто ввёл пароль (`admin_authorized`);
- данные заблокированного сообщения хранятся в `blocked_pending.json` и переживают перезапуск;
- хранятся последние 200 заблокированных сообщений;
- повторное нажатие после публикации выдаёт «уже опубликована или устарела».

## 👑 Царь-батюшка (шутливый судья споров)

Работает **только в боте 1** и **только в чате обсуждений** (`BOT1_DISCUSSION_CHAT_ID`). В личке и других чатах команда игнорируется.

В чате обсуждений напишите:

```
/царь батюшка реши спор кто не прав -20
@user1 @user2 123456789
```

- начало `/царь батюшка реши спор кто не прав` — команда;
- `-20` — просто для вида, количество сообщений не анализируется;
- дальше перечисляются участники спора: `@username` и/или числовые ID;
- участники, которых нет в чате, всё равно попадают в вердикт.

Что происходит: бот пишет «📖 Читаю сообщения...», через ~3 секунды удаляет, пишет «🤔 Думаю...», через ~2 секунды удаляет и публикует вердикт: **один участник прав, все остальные — нет**.

- без ИИ: если подкрутки нет — правый выбирается случайно;
- если среди участников есть подкрученный — правым становится он;
- если подкрученных несколько — правый выбирается случайно среди них;
- кулдаун — 3 минуты на чат. При повторном вызове бот пишет, сколько ждать, и удаляет это сообщение через ~8 секунд.

### Настройки в админке

Бот 1 → `/admin <пароль>` → **👑 Царь-батюшка**:

- включить/выключить функцию (при выключении команда полностью игнорируется);
- задать подкрутку — `@username` или числовой ID (можно несколько через пробел);
- посмотреть текущую подкрутку и сбросить её.

Настройки сохраняются в `settings.json` (`tsar_enabled`, `tsar_rigged`). На Render диск эфемерный, поэтому после деплоя подкрутку нужно задать заново.

## Запуск локально
```bash
pip install -r requirements.txt
cp .env.example .env
# Заполните BOT1_TOKEN и BOT2_TOKEN в .env
python main.py
```

## Деплой на Render
1. Создайте **Web Service** на [Render](https://render.com).
2. Подключите репозиторий.
3. Настройки сервиса:
   - **Environment:** `Python 3`
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `python main.py`
4. В **Environment Variables** добавьте переменные из `.env.example`:
   - `BOT1_TOKEN` (токен первого бота)
   - `BOT2_TOKEN` (токен второго бота)
   - `ADMIN_ID` (ID администратора)
   - и другие параметры каналов/модерации при необходимости.
5. Render автоматически выставит `$PORT`, встроенный HTTP-сервер будет отвечать `200 OK` для прохождения healthcheck.

## Деплой так, чтобы код не утёк на GitHub

Render не умеет загружать ZIP: он деплоит либо из Git-репозитория (публичного **или приватного**), либо из Docker-образа. Значит вариантов два.

### Вариант 1 — приватный репозиторий (рекомендую)

1. Создайте **приватный** репозиторий на GitHub (не форкайте публичный).
2. Запушьте туда код. Убедитесь, что `.gitignore` исключает `.env` и `*.json` с данными пользователей — он уже в проекте.
3. В Render: **New → Web Service → Build and deploy from a Git repository**, авторизуйте GitHub App и выдайте ему доступ к этому приватному репозиторию.
4. В **Environment** задайте `BOT1_TOKEN`, `BOT2_TOKEN`, `ADMIN_ID`, `ADMIN_SECRET`, `SE_USER`, `SE_SECRET` и остальные переменные.
5. Если старый репозиторий был публичным — переведите его в **Settings → Danger Zone → Change visibility → Private**, а лучше удалите и создайте новый: форки, кэш и история копий уже могли разойтись.

### Вариант 2 — приватный Docker-образ

Если GitHub использовать не хотите вообще: соберите образ локально, запушьте в приватный registry (GHCR/Docker Hub) и в Render выберите **Deploy an existing image**. Код при этом лежит только у вас и в registry.

### Важно про секреты

Если репозиторий уже был публичным, считайте все секреты скомпрометированными:

- перевыпустите токены ботов через `@BotFather` (`/revoke`);
- перевыпустите `SE_USER` / `SE_SECRET` в кабинете Sightengine;
- храните значения только в Render Environment (и локально в `.env`).

Данные ботов (`anon_logs.json`, `bot_state.json`, `manual_ids.json` и т.д.) в git не коммитятся. На Render диск эфемерный — при каждом деплое/перезапуске состояние обнуляется; для постоянного хранения нужен внешний сторедж (Render Disk или БД).
